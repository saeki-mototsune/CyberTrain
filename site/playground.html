01Open a codespace

WhyVS Code in your browser, on a cloud machine that runs on your own GitHub quota.

Open in GitHub Codespaces→ Read the tutorial

A GitHub account is required, and the codespace runs on your own Codespaces quota: GitHub's free plan includes 120 core-hours and 15 GB-month of storage a month, about 60 hours on the default 2-core machine the playground uses. GitHub stops an idle codespace after 30 minutes by default; its storage counts until you delete it.

02What opens

  • The blog with tutorial steps 02, 03, 04 and 07 done: cybertrain new blog, the article scaffold, the root route and the first migration, built once so the server starts without compiling.
  • A terminal running cybertrain server.
  • The app in the editor's preview, showing the article list.
  • PLAYGROUND.md, the short guide to what to try.
  • Source Control: the app is a git repository with one commit, so it shows exactly what you change.

03What to try

  • Edit a view. It shows on the next reload: views are read from disk on every request.
  • Add a validation. Ruby is compiled, so a Ruby change is a full rebuild, about a minute, after which the server restarts by itself.
  • Carry on with the tutorial from step 08, Scaffold comments.
  • Start a fresh app. cybertrain new works in the codespace with no network.

The preview does not reload by itself: press its reload button after a change. Inside the preview, pop-ups and confirm() dialogs do not work; the Ports view's “Open in Browser” shows the app in a normal tab.

04Run it with Docker

WhyThe same image runs on your own machine.

Then open http://localhost:3000. The published image is linux/amd64; on an arm64 machine, build it from a checkout as playground/README.md describes.

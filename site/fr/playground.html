CyberTrain / Bac à sable

Essayez dans votre navigateur

Le blog du tutoriel, déjà créé, avec son scaffold généré et ses migrations appliquées, s’ouvre dans VS Code dans votre navigateur, avec son serveur de développement lancé dans un terminal et l’application dans un nouvel onglet. Rien à installer : GitHub Codespaces l’exécute sur une machine dans le cloud.

Prérequis
Un compte GitHub

Votre propre quota Codespaces, sur la machine 2 cœurs par défaut

01Ouvrir un codespace

PourquoiVS Code dans votre navigateur, sur une machine dans le cloud qui consomme votre propre quota GitHub.

Ouvrir dans GitHub Codespaces→ Lire le tutoriel

Un compte GitHub est nécessaire, et le codespace consomme votre propre quota Codespaces : l’offre gratuite de GitHub inclut 120 heures-cœur et 15 Go-mois de stockage par mois, soit environ 60 heures sur la machine 2 cœurs par défaut qu’utilise le bac à sable. Par défaut, GitHub arrête un codespace inactif au bout de 30 minutes ; son stockage est décompté jusqu’à ce que vous le supprimiez.

02Ce qui s’ouvre

  • Le blog avec les étapes 02, 03, 04 et 07 du tutoriel déjà faites : cybertrain new blog, le scaffold des articles, la route racine et la première migration, compilé une fois pour que le serveur démarre sans compiler.
  • Un terminal qui exécute cybertrain server.
  • L’application dans un nouvel onglet, qui affiche la liste des articles.
  • PLAYGROUND.md, le petit guide de ce qu’il faut essayer.
  • Le panneau Source Control : l’application est un dépôt git avec un seul commit, il montre donc exactement ce que vous modifiez.

Si VS Code vous demande si vous faites confiance aux auteurs des fichiers de ce dossier, choisissez « Trust Folder & Continue » : le terminal du serveur ne démarre qu’à ce moment-là.

03À essayer

  • Modifiez une vue. Le changement apparaît au rechargement suivant : les vues sont lues depuis le disque à chaque requête.
  • Ajoutez une validation. Ruby est compilé, donc une modification Ruby implique une recompilation complète, environ une minute, après quoi le serveur redémarre tout seul.
  • Poursuivez le tutoriel à partir de l’étape 08, Scaffold des commentaires.
  • Créez une nouvelle application. cybertrain new fonctionne dans le codespace sans réseau.

L’onglet de l’application ne se recharge pas tout seul : rechargez-le après une modification. Si l’onglet de l’application ne s’est pas ouvert (bloqueur de pop-up, ou codespace arrêté puis redémarré), utilisez « Open in Browser » dans la vue Ports, sur le port 3000.

04Lancer avec Docker

PourquoiLa même image tourne sur votre propre machine.

Ouvrez ensuite http://localhost:3000. L’image publiée est en linux/amd64 ; sur une machine arm64, construisez-la à partir d’une copie du dépôt, comme le décrit playground/README.md.

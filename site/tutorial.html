00Requirements

WhyCyberTrain compiles through Spinel to C, so it needs the toolchain and the SQLite headers.

  • Spinel 2026.09.12, with spinel and spin on PATH. Untested against other versions.
  • A C toolchain (cc).
  • SQLite 3 headers and library: libsqlite3-dev on Debian/Ubuntu; present with Xcode's command line tools on macOS.
  • Building Spinel itself also needs OpenSSL headers (libssl-dev). CyberTrain does not link OpenSSL.

06The ArticlesController

WhyFull CRUD, Rails-shaped down to strong params and flash-then-redirect, except for two things Spinel forces everywhere.

Spinel rule

new_action, not new

A method literally named new would shadow ArticlesController.new(ctx), which the framework uses to construct the controller. The route GET /articles/new still maps to it; you only rename the method. The view is still new.html.erb and render :new is unchanged.

Spinel rule

Callbacks take the controller explicitly

There is no instance_exec on a stored block, so a block callback receives the controller (or the record) as an argument: before_action { |c| c.do_thing }, not before_action { do_thing }. Actions and callbacks are called by their literal name, never send.

The scaffold writes the full controller with index, show, edit, update and destroy too; the excerpt above omits them. In index, @articles = Article.all.to_a: the .to_a is required.

Instance variables are found by a lexical scan of @ivar =, so re-run spin run gen after adding one.

You are here:Build time, then run time · gen/ → build/bin/server

07Generate, migrate, run

WhyTurn schema and routes into gen/, create the SQLite database, start the server.

On a brand-new scaffold, run spin run gen once more after migrate so gen/ picks up the rewritten db/schema.rb.

  • The -- before migrate is required: arguments go after --.
  • Re-run spin run gen and commit gen/ after touching the schema, routes, or a controller's or model's callbacks and ivars. The development server does this for you.
  • Change the port with PORT=4000.

Spinel rule

There is no console

rails console has no counterpart: Spinel has no eval. Ruby changes need a rebuild, which spin run server does for you in development (rebuild, SIGHUP, execv). Views are parsed from disk per request, so editing one needs no rebuild.

09Nest the routes

WhyRails' guide nests comments under articles.

Spinel rule

Nested blocks take the mapper explicitly

Write resources :articles do |articles| and articles.resources :comments, not a bare resources :comments. Spinel's instance_eval trampoline only rewires self for the outermost block.

Spinel rule

Views are a closed grammar, not Ruby

Spinel has no eval, so templates are interpreted against a fixed grammar. link_to has no method: option; use button_to. each takes one or two block parameters. A strict-locals comment such as <%# locals: (comment:) %> takes no default values. A partial gets a copy of the caller's environment, so @article is visible in comments/_form. See docs/template-language.md.

12Test it

Whyminitest and RSpec find tests by reflection, which an ahead-of-time compiler cannot do, so CyberTrain ships Cybertrain::Test.

A model test

Assertions: assert, refute, assert_equal, assert_nil, assert_includes, assert_raises("Class") { }, flunk. The example also uses assert_response and assert_redirected_to.

A full HTTP flow

Cybertrain::Test::Client drives an app in-process (no socket) with a cookie jar, so sessions and CSRF behave as behind a browser. Requests without the token get a 403.

Before it compiles

What the snippets leave out

  • End the file with Cybertrain::Test.run!, and require "cybertrain/test" (or a helper that does) yourself; otherwise test "..." fails to compile.
  • BLOG and token come from examples/blog/test/support/blog_test.rb, which migrates a fresh storage/test.sqlite3, builds the app and extracts the CSRF token from a rendered form.
  • Set c.log_level = :none if c.test? in config/app.rb to keep request logs out of the compared output.

Run the tests

spin test compiles and runs every program under test/ and diffs its output against a committed test/<name>.rb.expected snapshot. Files in test/support/ are required, not run. To write a snapshot:

--regen writes the snapshot from CRuby's output. Tests that touch SQLite through FFI can't run under CRuby, so their snapshot comes from the compiled binary (the second command). Every test needs its .expected file before spin test can pass.

13Ship it

WhyOne command builds the server binary.

This produces build/bin/server. The binary alone does not run. What you ship:

  • build/bin/serverthe compiled framework, controllers, models and template interpreter
  • app/views/read at request time, never compiled in
  • public/static assets, or let a reverse proxy serve it
  • storage/the SQLite file

Set CYBERTRAIN_ENV=production and CYBERTRAIN_SECRET_KEY_BASE. For illustration:

Cybertrain::Config reads the environment first; config/app.rb overrides:

VariableAttributeDefault
CYBERTRAIN_ENVenv"development" (also "test", "production")
PORTport3000
CYBERTRAIN_DATABASEdatabase_pathstorage/#{env}.sqlite3
CYBERTRAIN_SECRET_KEY_BASEsecret_key_baserequired in production; dev/test auto-generate one into tmp/secret_key
SPINEL_WORKERSworkers1
  • The server speaks plain HTTP/1.1: put nginx or Caddy in front for TLS and HTTP/2.
  • Production refuses to start without CYBERTRAIN_SECRET_KEY_BASE.
  • The default bind host is 127.0.0.1; host is a Config attribute that config/app.rb can set.
  • The watcher and rebuild loop never run in production.

+Things to know

WhyLimits and quirks worth knowing before they surprise you.

  • Sessions hold Strings only, in an HMAC-signed cookie.
  • SQLite only, through Spinel’s FFI.
  • No backtraces: errors show class, message, request line and template name/line.
  • A misspelled attribute in a view renders blank instead of raising; the template language reference tracks this as a known gap.
  • Associations come from schema foreign keys only; no has_many :through, includes, pluck, dependent:, enums, STI or polymorphic associations.
  • No namespace, respond_to/formats, constraints or mount; render json: is minimal.
  • Only the first string field gets a default presence validation in a scaffolded model.
  • The generator uses a lexical scan (regexes), not a parser, over app/controllers and app/models.
  • SPINEL_WORKERS defaults to 1.
  • Only Spinel 2026.09.12 is tested.

Differences between Rails and CyberTrain (full table from the README)
RailsCyberTrain
rails consoleNo console — Spinel has no eval
Edit code, the running app picks it upRuby needs a rebuild; spin run server in development does this for you (rebuild, SIGHUP, execv)
Edit a view, no reload neededSame — views are parsed from disk per request in development
def newdef new_action (new would shadow Klass.new(ctx))

ERB compiles to a method; any object, any methodInterpreted against a fixed grammar/dispatch table — docs/template-language.md
Session holds any marshalled objectSession values are Strings only, HMAC-signed cookie
Many database adaptersSQLite only, via FFI
has_many :through, includes, pluck, dependent:, enums, STI, polymorphic associationsNot implemented; associations come from schema foreign keys only
namespace, format/respond_to, constraints, mountNot implemented — flat names, render json: only

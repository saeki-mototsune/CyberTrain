CyberTrain / プレイグラウンド

ブラウザで試す

チュートリアルのブログが、作成・スキャフォールド・マイグレーションまで済んだ状態で、ブラウザ上の VS Code で開きます。開発サーバーはターミナルで起動しており、アプリは新しいブラウザタブに表示されます。インストールは不要です：GitHub Codespaces がクラウド上のマシンで実行します。

必要なもの
GitHub アカウント
実行環境
あなた自身の Codespaces の利用枠（デフォルトの 2 コアマシン）
使えるもの
VS Code、Spinel 2026.09.12、cybertrain CLI、そしてブログ

現在地:インストール不要 · GitHub Codespaces

01codespace を開く

なぜブラウザ上の VS Code を、あなた自身の GitHub の利用枠で動くクラウドマシンで。

GitHub Codespaces で開く→ チュートリアルを読む

GitHub アカウントが必要で、codespace はあなた自身の Codespaces の利用枠で動きます：GitHub の無料プランには毎月 120 コア時間と 15 GB-月のストレージが含まれており、プレイグラウンドが使うデフォルトの 2 コアマシンで約 60 時間分です。GitHub はデフォルトで、アイドル状態の codespace を 30 分後に停止します。ストレージは codespace を削除するまで使用量に計上されます。

02開かれるもの

  • チュートリアルのステップ 02、03、04、07 を済ませたブログ：cybertrain new blog、記事のスキャフォールド、root ルート、最初のマイグレーション。一度ビルド済みなので、サーバーはコンパイルなしで起動します。
  • cybertrain server を実行中のターミナル。
  • 新しいブラウザタブで記事一覧を表示しているアプリ。
  • PLAYGROUND.md：何を試せばよいかの短いガイド。
  • ソース管理（Source Control）：アプリはコミットがひとつだけの git リポジトリなので、あなたが変更した内容が正確に表示されます。

このフォルダー内のファイルの作成者を信頼するかどうかを VS Code に尋ねられたら、「Trust Folder & Continue」（フォルダーを信頼して続行）を選んでください：サーバーのターミナルはそのときに初めて起動します。

03試してみること

  • ビューを編集する。次にリロードしたときに反映されます：ビューはリクエストのたびにディスクから読み込まれます。
  • バリデーションを追加する。Ruby はコンパイルされるため、Ruby の変更は完全な再ビルド（約 1 分）になり、その後サーバーは自動で再起動します。
  • チュートリアルの続きを進める：ステップ 08「コメントをスキャフォールドする」から。
  • 新しいアプリを始める。cybertrain new は codespace 内でネットワークなしで動きます。

アプリのタブは自動ではリロードされません：変更後にリロードしてください。アプリのタブが開かなかった場合（ポップアップブロッカーのせいか、codespace が停止・再起動された場合）は、「ポート」ビューでポート 3000 の「Open in Browser」（ブラウザーで開く）を使ってください。

04Docker で実行する

なぜ同じイメージが手元のマシンでも動きます。

次に http://localhost:3000 を開きます。公開されているイメージは linux/amd64 です。arm64 のマシンでは、playground/README.md の説明に従ってチェックアウトからビルドしてください。

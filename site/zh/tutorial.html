00环境要求

为什么CyberTrain 通过 Spinel 编译为 C，所以需要 C 工具链和 SQLite 头文件；cybertrain 命令是一个 gem，所以需要 Ruby。

  • Ruby 3.2+ 和 RubyGems，仅供 cybertrain 命令使用；应用本身从不在 CRuby 上运行。
  • Spinel 2026.09.12，未在其他版本上测试。你无需手动安装：第一个需要它的命令会把该版本构建到 ~/.cybertrain 中（需要几分钟，仅一次），除非 PATH 上已有该版本的 spinel。
  • C 工具链（cc，或 CC 指定的编译器）和 make，以及 git 和 curl，用于构建 Spinel；Spinel 会把每个程序编译为 C。
  • SQLite 3 和 zlib 头文件和库：Debian/Ubuntu 上为 libsqlite3-dev 和 zlib1g-dev；macOS 上随 Xcode 命令行工具提供。
  • OpenSSL 头文件（libssl-dev）是可选的：没有它们时，Spinel 构建时会不带其 openssl 包，而 CyberTrain 并不使用这个包。

cybertrain doctor 会检查这些工具和头文件以及 Spinel 的安装情况；缺少必需项时，它还会打印适用于你的平台的安装命令。

CyberTrain 如何安装 Spinel某个命令首次需要 spin 时会发生什么

cybertrain new、db、server、build 和 spin 会先查找 Spinel 2026.09.12：首先是 PATH 上已有的该版本的 spinel 和 spin，其次是 ~/.cybertrain/spinel/2026.09.12/ 下的副本；如果都没有，就从 Spinel 的发布标签构建这份副本（git clone、make deps、make -j、make install），只需一次，耗时几分钟。日志位于 ~/.cybertrain/log/spinel-2026.09.12-build.log；如果缺少构建所需的工具，cybertrain 会在开始前指出缺少哪个，并打印适用于你的平台的安装命令。

cybertrain setup 会按需执行同样的操作（--force 会重新构建 ~/.cybertrain 下的副本），并且在正在使用的是它自己的副本时，打印把它加入 PATH 的那一行，方便你自己运行 spin：

~/.cybertrain/bin 中存放指向当前所用版本的 spinel 和 spin 链接。即使它不在 PATH 上，cybertrain spin ARGS... 也能在任意目录下用该版本运行 spin。CYBERTRAIN_HOME 可替代 ~/.cybertrain，CYBERTRAIN_SPINEL_HOME=PREFIX 则改用安装在 PREFIX 中的 Spinel（必须是该版本）。PATH 上其他版本的 spinel 永远不会被使用或改动。

没有可以安装的机器？在线试用会在 GitHub Codespace 中打开这个博客，第 02、03、04 和 07 步都已完成。

01安装 CLI

为什么cybertrain 命令用来创建应用、生成资源脚手架、执行迁移、启动服务和构建。

第一行从 RubyGems 安装它。其余几行是整个教程的概览；下面的步骤会逐条命令讲解。

cybertrain 命令是纯 Ruby 编写的，gem 在 CRuby（3.2 或更新版本）下运行它；框架和 Spinel 都不在这个 gem 里。它的命令如下（cybertrain help 会把它们打印出来）：

  • cybertrain new NAME [--path DIR | --version V | --git URL [--ref R]] [--skip-spin] 在 NAME 中创建应用，然后在其中运行 spin lock 和 spin run gen，需要时会先安装 Spinel。
  • cybertrain generate scaffold NAME field:type ...（别名 g scaffold）为当前目录中的应用添加一个资源。
  • cybertrain generate authentication 为当前目录中的应用添加用邮箱和密码登录的功能（步骤 13）。
  • cybertrain generate attachment MODEL FIELD [--any] 为当前目录中应用里已生成脚手架的模型添加文件上传功能（步骤 14）。
  • cybertrain db migrate 先生成代码，再执行待处理的迁移，然后再次生成（spin run gen; spin run db -- migrate; spin run gen）；cybertrain migration 作为别名保留。
  • cybertrain db COMMAND... 在 spin run gen 之后运行其他任意数据库命令：status、rollback [N]（之后会再次生成）、schema:dump、create。
  • cybertrain server [PORT] 先生成代码，然后启动开发服务器（spin run gen; spin run NAME，或 spin run NAME -- PORT；默认端口 3000）。
  • cybertrain build 构建嵌入了 app/views/ 的 NAME，并组装 dist/（二进制文件、public/、storage/、tmp/）。
  • cybertrain spin ARGS... 在任意目录下用锁定版本的 Spinel 运行 spin：cybertrain spin test、cybertrain spin run gen -- --check。
  • cybertrain setup [--force] 把 Spinel 2026.09.12 安装到 ~/.cybertrain 中，除非 PATH 上已有该版本的 spinel；--force 会重新构建 ~/.cybertrain 下的副本。
  • cybertrain doctor 检查 C 工具链、SQLite 头文件和 Spinel 的安装情况。
  • cybertrain version 打印版本（cybertrain 0.2.1）；cybertrain help 打印用法。

db、server 和 build 需在应用目录内运行；NAME 是其 spin.toml 中的 [package] name。

06ArticlesController

为什么完整的 CRUD，连强参数和“先 flash 再重定向”都是 Rails 风格的，只有两处是 Spinel 处处强制要求的。

Spinel 规则

new_action，而不是 new

名字恰好叫 new 的方法会遮蔽 ArticlesController.new(ctx)，而框架要用它来构造控制器。路由 GET /articles/new 仍然映射到这个方法；你只需重命名方法。视图仍然是 new.html.erb，render :new 也保持不变。

Spinel 规则

回调显式接收控制器

无法对存储的块使用 instance_exec，所以块形式的回调会以参数形式接收控制器（或记录）：写 before_action { |c| c.do_thing }，而不是 before_action { do_thing }。动作和回调都按字面名称调用，从不使用 send。

脚手架写出的完整控制器还包含 index、show、edit、update 和 destroy；上面的节选省略了它们。在 index 中写的是 @articles = Article.all.to_a：其中的 .to_a 是必需的。

实例变量是通过对 @ivar = 的词法扫描找到的，所以新增实例变量后要重新运行 cybertrain spin run gen；开发服务器会替你完成这一步。

07生成、迁移、运行

为什么把 schema 和路由转换成 gen/，创建 SQLite 数据库，启动服务器。

spin run gen 读取 db/schema.rb 和 config/routes.rb，扫描 app/ 并写入 gen/；spin run db -- migrate 执行 db/migrate/*.rb 并重写 db/schema.rb。顺序很重要：第一次 spin run gen 把新迁移放进 gen/migrations.rb（bin/db.rb 会 require 它），第二次则根据重写后的 db/schema.rb 构建模型。

cybertrain server 会打印它运行的每条 spin 命令，然后是应用的启动横幅。第一次启动需要编译应用，所以要花一些时间：

  • 修改 schema、路由，或者控制器、模型的回调和实例变量之后，重新运行 cybertrain spin run gen 并提交 gen/。开发服务器会替你完成这一步。
  • 用 cybertrain server 4000（或 PORT=4000）更改端口。
  • spin run db 要求在参数前加上 --，cybertrain db 会替你加上；cybertrain db status 和其他数据库命令也是如此。

Spinel 规则

没有控制台

rails console 没有对应的功能：Spinel 没有 eval。修改 Ruby 代码需要重新构建，开发时 cybertrain server 会替你完成（重新构建、停止、execv）。开发时视图在每次请求时从磁盘解析，所以修改视图无需重新构建；cybertrain build 会为生产环境把它们嵌入。

12测试

为什么minitest 和 RSpec 通过反射查找测试，而 AOT 编译器做不到这一点，因此 CyberTrain 提供了 Cybertrain::Test。

模型测试

断言：assert、refute、assert_equal、assert_nil、assert_includes、assert_raises("Class") { }、flunk。示例中还用到了 assert_response 和 assert_redirected_to。

完整的 HTTP 流程

Cybertrain::Test::Client 在进程内（不经过 socket）驱动应用，并带有 cookie jar，所以会话和 CSRF 的行为与在浏览器中一致。不带令牌的请求会得到 403。

编译之前

片段中省略的内容

  • support/blog_test 就是 examples/blog/test/support/blog_test.rb：把它复制到你的应用的 test/support/ 中，这里的文件会被 require，而不会被运行。它会迁移一个全新的 storage/test.sqlite3，以 BLOG 启动应用，加载 Cybertrain::Test 及其客户端，并提供 BlogTest.form_token（最近渲染的表单中的 CSRF 令牌）和 BlogTest.article_path。
  • 在文件末尾调用 Cybertrain::Test.run!，它会运行测试，并打印快照所比对的各行输出。
  • 在 config/app.rb 中设置 c.log_level = :none if c.test?，让请求日志不进入被比对的输出。

运行测试

cybertrain spin test 用锁定版本的 Spinel 运行 spin test；如果工具链已在 PATH 上（第 00 步），直接运行 spin test 效果相同。它会把每个 test/*.rb 编译成独立的程序，并将其输出（stdout 和 stderr 合在一起）与已提交的快照 test/<name>.rb.expected 进行比对。test/support/ 中的文件会被 require，而不会被运行。要写入快照：

Spinel 规则

has_one_attached 被逐一写出

Spinel 无法在运行时定义方法（没有 define_method），所以没有 has_one_attached，也没有共享的附件表。生成器把它本会定义的东西逐一写出，成为以字段命名的方法，放在 Article 中，并把元数据放进 articles 的五个列里。这些列都是 NOT NULL，用 "" 和 0 表示“没有附件”：可为空的列会让 Spinel 失去类型推断。SQLite 只保存元数据（文本值遇到 NUL 字节就会截断）；字节保存在文件里。

文件如何提供

  • 类型。 默认只接受不超过 2 MB 的 PNG、JPEG、GIF 和 WebP（COVER_TYPES and COVER_MAX_BYTES 在模型中；--any 则接受任何类型）。类型由文件的前几个字节检测，绝不采用浏览器给出的值。
  • 存储。 字节保存到 storage/uploads/<2 hex>/<32 hex key>（Cybertrain::BlobStore，权限 0600）。替换文件会删除旧文件，销毁文章会删除它的文件。请把 storage/uploads/ 和 SQLite 文件一起备份。
  • 提供。 文件通过控制器中的 send_blob 发出，绝不从 public/ 提供。四种图片类型内联显示；其他类型一律作为下载（application/octet-stream）。每个响应都带有 X-Content-Type-Options: nosniff 和 Content-Security-Policy: default-src 'none'; sandbox。
  • 参数。 params.nested(:article).upload(:cover) 是一个 Cybertrain::UploadedFile，没有选择文件时为 nil。permit 从不返回文件，所以文件只能通过那一行显式的代码进入。CSRF 令牌和普通表单一样，从 multipart 请求体中读取。损坏或过大的请求体会得到 400；限制由 config/app.rb 中的 max_upload_bytes 和 max_multipart_parts 设置，存放目录由 upload_root 设置。

启动服务器，编辑一篇文章并选择一张图片。生成器还写了 test/attachment_article_cover.rb，它测试整个流程，并且因为应用现在有了 User，会先登录。由于这里的 :cover 是公开的，它会检查访客能否下载封面；正文则填入 "A article."，长度补足到 步骤 05 要求的至少 10 个字符。

和步骤 12 一样用 cybertrain spin test 运行；这个测试会用到 SQLite，所以它的快照来自编译后的二进制。examples/blog 止步于这一步之前。尚未实现：每个字段多个文件、S3 或其他远程存储、图片变体，以及把大请求体流式写入磁盘（整个请求体会读入内存，上限为 max_body_bytes）。

这会写出 dist/：嵌入了所有视图的应用二进制文件，以及放在它旁边、供它使用的文件。它会运行 spin run gen -- --embed-views、spin build blog 和 spin run gen（最后这一步会恢复已提交的、空的 gen/views.rb，即使在失败或按下 Ctrl-C 之后也是如此），然后组装出：

+须知

为什么值得提前了解的限制和特殊之处，免得到时措手不及。

  • 会话只能保存 String，存放在 HMAC 签名的 cookie 中。
  • 仅支持 SQLite，通过 Spinel 的 FFI 访问。
  • 没有回溯（backtrace）：错误只显示类、消息、请求行以及模板名/行号。
  • 视图中拼错的属性会渲染为空白，而不会抛出异常；这是一个已知的不足。
  • 关联只来自 schema 中的外键；不支持 has_many :through、includes、pluck、dependent:、枚举、STI 或多态关联。
  • 不支持 namespace、respond_to/格式、constraints 或 mount；render json: 只有最基本的功能。
  • 在脚手架生成的模型中，只有第一个字符串字段会获得默认的存在性验证。
  • 生成器对 app/controllers 和 app/models 使用词法扫描（正则表达式），而不是解析器。
  • 视图在构建时嵌入：即使只修改了视图，也需要运行 cybertrain build 并重启，改动才能到达生产环境。
  • 在与运行机器相同的操作系统和 CPU 上构建 dist/：该二进制文件链接系统的 SQLite。
  • SPINEL_WORKERS 默认为 1。
  • 只测试过 Spinel 2026.09.12。

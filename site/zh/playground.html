CyberTrain / 在线试用

在浏览器中试用

教程中的博客已经创建好、生成了脚手架并完成了迁移，会在浏览器中的 VS Code 里打开，开发服务器在终端中运行，应用则在新的浏览器标签页中打开。无需安装任何东西：GitHub Codespaces 在云端机器上运行它。

01打开 codespace

为什么浏览器中的 VS Code，运行在使用你自己 GitHub 配额的云端机器上。

在 GitHub Codespaces 中打开→ 阅读教程

需要 GitHub 账号，并且 codespace 使用你自己的 Codespaces 配额运行：GitHub 免费计划每月包含 120 核心小时和 15 GB-月的存储，在在线试用所用的默认 2 核机器上大约可运行 60 小时。默认情况下，codespace 空闲 30 分钟后 GitHub 会将其停止；在你删除它之前，其存储都会计入用量。

02打开的内容

  • 已完成教程第 02、03、04 和 07 步的博客：cybertrain new blog、文章脚手架、根路由和第一次迁移，并且已经构建过一次，所以服务器无需编译即可启动。
  • 一个正在运行 cybertrain server 的终端。
  • 在新的浏览器标签页中打开的应用，显示文章列表。
  • PLAYGROUND.md，一份介绍可以尝试什么的简短指南。
  • 源代码管理：应用是一个只有一次提交的 git 仓库，因此能准确显示你修改了什么。

如果 VS Code 询问你是否信任此文件夹中文件的作者，请选择 “Trust Folder & Continue”（信任文件夹并继续）：只有这样，服务器的终端才会启动。

03可以尝试什么

  • 修改一个视图。下次重新加载时就会显示：每次请求都会从磁盘读取视图。
  • 添加一个验证。Ruby 是编译执行的，所以修改 Ruby 代码会触发一次完整的重新构建，大约需要一分钟，之后服务器会自行重启。
  • 继续学习教程，从第 08 步：生成评论脚手架开始。
  • 新建一个应用。在 codespace 中，cybertrain new 无需网络即可运行。

应用的标签页不会自动重新加载：修改后请手动重新加载。如果应用的标签页没有打开（被弹出窗口拦截，或者 codespace 停止后又重新启动），请在“端口”视图中对端口 3000 使用 “Open in Browser”（在浏览器中打开）。

04用 Docker 运行

为什么同一个镜像也可以在你自己的机器上运行。

然后打开 http://localhost:3000。发布的镜像是 linux/amd64 的；在 arm64 机器上，请按照 playground/README.md 中的说明，从检出的源码构建它。

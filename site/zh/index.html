预 Alpha·Spinel·MIT

Rails 风格的 Web 应用，编译为单个原生二进制文件。

像在 Rails 里一样编写路由、控制器、模型和 ERB 视图，脚手架也一样。cybertrain build 通过 matz 的 Ruby 预先编译器 Spinel，把它们连同框架一起编译成一个原生二进制文件：生产环境中没有 Rack，没有 gem，也没有 Ruby 解释器。

开始教程→ 在浏览器中试用 阅读指南

快速上手

需要 Ruby 3.2+（带 fiddle）、git、make、curl、C 编译器，以及 SQLite 3、zlib 和 OpenSSL 的头文件；cybertrain doctor 会检查它们（环境要求）。构建产物本身不需要 Ruby：设置好 CYBERTRAIN_SECRET_KEY_BASE 后运行 cd dist && ./blog migrate && ./blog。

  • Rails 风格熟悉的词汇resources、before_action、validates、form_with 和脚手架，与 Rails 一样。
  • 一个二进制文件生产环境无需 Ruby你的应用和框架被编译进 dist/：没有 Rack，没有 gem，没有解释器。
  • 快速而轻量与 Rails 8.1 对比实测每秒处理更多请求，只用一小部分内存：看数据。
  • 部署简单一个二进制文件，一个 SQLite 文件放在 Caddy 或 kamal-proxy 后面；cybertrain new 会写好 Kamal 配置。部署。

适合谁，不是什么

面向想要单个原生二进制文件、并且能接受一个年轻项目和 Ruby 子集的 Rails 开发者。

  • 不能原样运行 Rails 代码

    应用用 Spinel 的 Ruby 子集、针对 CyberTrain 的 API 编写：没有 Rack，运行时除了 Spinel 自己的 spin-index 包之外也没有 gem。手工移植 Rails 应用是目标之一，由 Rails 应用创建的 SQLite 数据库可以原样接管。

  • 尚不可用于生产

    CyberTrain 处于预 Alpha 阶段。示例博客由 CI 在 Linux 和 macOS 上运行测试。

01

你编写的代码

沿用 Rails 的词汇，Spinel 的规则全部写明。

控制器、模型、路由和视图读起来就像一个 Rails 应用。凡是 AOT 编译器迫使其有所不同的地方，差异都很小、很明确，并且有文档说明。

  • 路由

    嵌套的 resources 块需要显式接收 mapper：articles.resources :comments。

  • 控制器

    new 要写成 new_action：生成的路由按这个名字调用该动作。

  • 视图

    开发时模板从磁盘读取，所以修改视图无需重新构建；cybertrain build 会把它们嵌入二进制文件。模板是一套封闭的语法，而不是任意 Ruby。

  • 模型

    class Article 声明验证；列、查找方法和关联都根据 db/schema.rb 生成。

03

工作原理

元编程只在构建时发生一次。

Spinel 进行 AOT 编译，没有 eval。因此，凡是 Rails 在运行时借助 method_missing 和 define_method 的地方，spin run gen 都会写出你可以阅读和提交的纯 Ruby 代码，只有视图是解释执行的。

  1. 1

    构建时生成

    spin run gen 读取 db/schema.rb 和 config/routes.rb，扫描 app/controllers 和 app/models，并把可读的纯 Ruby 代码写入 gen/。cybertrain db migrate、server 和 build 会替你运行它。

  2. 2

    提交 gen/

    它要提交进仓库，因为 spin build 和 spin test 没有可以先执行生成的钩子。CI 会重新运行 spin run gen，一旦有差异就失败，因此过时的生成代码无法合并。

  3. 3

    解释执行视图

    一个遍历树的解释器渲染 app/views/**/*.html.erb：开发时从磁盘读取，由 cybertrain build 嵌入二进制文件。Spinel 没有 eval，所以这是一套封闭的语法，而不是真正的 Ruby。

  4. 4

    用绿色线程提供服务，用 SQLite 存储

    纯 Ruby 编写的 HTTP/1.1 服务器 spinel-http 为每个连接运行一个 Spinel 绿色线程。模型通过 ffi_func/ffi_lib 访问 SQLite，使用 4 个连接的连接池。

  5. 5

    开发时先预览，再编译

    cybertrain server 在 Ruby 改动后立即用 CRuby 预览提供服务，在后台构建二进制文件，构建完成后把端口交给它（在 examples/blog 上约一分钟）。构建失败时预览继续提供服务，并以横幅显示编译器输出；cybertrain server --spinel 只运行编译版的循环。

AOT 编译器会改变一些习惯。下面是你最先会遇到的几条。

05

框架与 CLI

一个名字，两个部分。

gem install cybertrain 安装的是一个命令，而不是框架。框架是一个 Spinel 包，你的应用依赖它并把它编译进来。这个 gem 提供 cybertrain 命令，它会替你创建应用、安装 Spinel 并运行 Spinel 的工具。

Spinel 包

框架

你的应用所基于的库。

包含什么

路由和控制器、会话与 CSRF 防护、模板解释器、SQLite 模型和迁移、可选的子系统（作业、Turbo Streams、邮件、缓存）、测试框架，以及 spin run gen 背后的代码生成器。HTTP 服务器是 spinel-http，框架所依赖的一个独立库。

如何获取

你不需要安装它。你的应用的 spin.toml 指定本仓库与你的 cybertrain 命令相对应的发布标签，spin lock 会把它连同 spinel-http 一起拉取到 spin 的缓存中，并在 spin.lock 中锁定这两个提交。不会有任何内容被复制到你的应用中。

RubyGem

cybertrain 命令

用来创建、构建和运行你的应用的工具。

包含什么

只有 cybertrain 命令：new、generate（scaffold、authentication、attachment、job、component、helper）、db、server、build、test、secret、spin、setup、doctor 和 version。框架和 Spinel 都不在这个 gem 里。

如何获取

gem install cybertrain。首次使用时，它会把锁定的 Spinel 版本构建到 ~/.cybertrain 中，除非你的 PATH 上已经有该版本。

两者从同一个标签发布；如果应用的框架是另一个版本，命令会拒绝构建它。升级指南一步步说明如何把应用迁移到新版本。

06

性能

在一个核心上，处理的请求是 Rails 的 3.6 到 10.1 倍。

对比的是两个框架各自生成的东西：cybertrain new 生成的应用加上文章的脚手架，对比 Rails 8.1 中 rails new 生成的应用加上同样的脚手架，两者都保持生成时的原样，没有为基准测试编写任何代码。两者都以生产模式运行，固定在同一台机器的相同 CPU 核心上，由 wrk 施加相同的负载。第二个核心对 Rails 的帮助更大：Puma 会多开一个完整的进程，而 CyberTrain 的第二个工作线程只带来 34% 到 56% 的提升，因此在两个核心上差距为 1.8 到 7.5 倍。

服务器所有进程的常驻内存（从 /proc 读取的 RSS）之和，在全部负载运行结束后读取。Rails 在一个核心上运行一个 3 线程的 Puma 进程，在两个核心上运行两个工作进程和一个主进程。RSS 会把 Puma 进程间共享的页面按每个进程各算一次；按在进程间分摊共享页面的 PSS 计算，两个核心上的 Rails 占用 316.8 MB（使用 jemalloc 时为 282.5 MB），而 CyberTrain 为 27.0 MB（29.1 MB）。

  • 负载下的内存

    23.7 MB

    Rails：177 MB（一个 Puma 进程，3 个线程）。

  • 从启动到首个响应

    0.016 秒

    Rails：1.3 秒。

  • 服务器上需要的东西

    10.6 MB

    一个二进制文件。Rails：Ruby、94 个 gem 和应用，共 134 MB。

  • 代价：一次构建

    207 秒

    用 cybertrain build 编译二进制文件所需的时间。Rails 直接运行源代码。

预热之后三次 10 秒测量的中位数，环境为一台 4 vCPU 的云虚拟机（2.10 GHz 的 Xeon）：用锁定的 Spinel 版本构建的 CyberTrain（提交 a312f9ef），对比运行在 Ruby 3.4.6（启用 YJIT）和 Puma 8.1 上的 Rails 8.1.4.1。以前的测量对比的是 examples/blog 和用 Rails 重写的同一个博客，因此其数字不能与这些相比。测量方法、全部数字、每次运行之间的波动，以及两个脚手架之间的差异：docs/benchmark.md。

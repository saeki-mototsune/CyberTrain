# Phase 4b (i18n and authentication) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver part 4b of phase 4: Rails-shaped translations (`config/locales/*.yml` read by gen into `gen/locales.rb`, `t` / `l` / lazy lookup / `count:` plurals for en, fr, ru, ja and zh, bundled English and Japanese dictionaries that every framework string goes through) and the authentication generator's additions (password reset, `--confirmable`, lockout, account pages, remember me, an admin flag with `require_admin`, every generated string through `t()`, and an upgrade path for applications generated by 0.4).

**Architecture:** gen reads the dictionaries with one reader (Spinel's Psych behind a refusal pre-scan, or a hand-written subset parser: the spike decides) and emits a generated lookup compiled into the application; the framework's own English and Japanese dictionaries are YAML files under `cybertrain/locales/` turned into a checked-in Ruby lookup by a script, and the runtime tries the application's lookup, then the bundled one, then the default locale. The per-request locale is thread-local, reset at the top of every action. Authentication stays code the application owns: the generator now writes Rails 8's `app/controllers/concerns/authentication.rb` and the new controllers, mailers, views and tests; the framework adds only small pieces (signed tokens, a mail message with `deliver_later`, a per-session lifetime that `SessionStore` honours, `allow_unauthenticated_access`).

**Tech Stack:** Ruby compiled by Spinel 2026.11.04.7026 (also run under CRuby 3.3), SQLite via FFI, Spinel's openssl and (if the spike passes) psych packages, the `Gen::*` scanners and emitters, `Template::Helpers`, `Cybertrain::Session` / `SessionStore`, `Cybertrain::Crypto`, `Cybertrain::Mailer` and `Mailer.deliver_later`, `Relation#increment`, the test receivers (`Test::SmtpReceiver`) and `Test::Client`.

**Spec:** docs/superpowers/specs/2026-11-10-phase4-web-layer-design.md — sections 8 and 9, the 4b rows of sections 10 to 14 (§12 spike item 6), acceptance items 9 to 12 of section 15, and the 4b notes for section 18. Read §0–1 and §18 (what 4a learned) first. Survey of the code with exact names and lines: the controller's scratchpad `phase4b-survey.md` (its facts are restated where a task needs them).

**Execution notes:** Task 1 first: its results amend spec §12, and the tasks that depend on them (2, 3, 4) take the branch it records under R3, R4 and D3. ## Global Constraints

- **Closer to Rails, then easier to understand** decides every judgement call (spec §0): Rails' names, keys (rails-i18n's key layout), defaults, file layout and output; compatibility with 0.4 applications carries low weight (§14 lists each break).
- **No computed `send`, `public_send`, `const_get` or `constantize`** (spikes/NOTES.md rule 1): dictionary lookups are a generated `case` or Hash (Task 1 decides), helper names a `case` arm.
- **One return type per method name across the program** (rules 10, 34, 41): String lookups and Array lookups are separate methods (`I18n.t` / `I18n.translate_list`, `lookup` / `lookup_list`); every new clash-prone name has a row in `script/check-reserved-names`' `NAME_HOMES`, seeded in Task 1 with this plan's homes (a name the plan did not foresee is added by its task, which then runs outside any parallel group).
- **No stored block run through a base-class receiver** (rule 88): `rate_limit with:` takes a method name, never a lambda, in generated controllers; `I18n.with_locale` yields at once.
- **Rule 62 framework-wide**: every new method that scans a String byte by byte (the YAML reader, the plural rules, `Accept-Language`, token parsing) reads its parameter through a fresh local (`s = text.to_s`).
- Other Spinel rules in play: nullable ivars through nil-capable casts (7); seed polymorphic containers (9/46); `rescue` in a non-yielding method (32/45); messages built into a local before `raise` (58); a yield's value into a local before a method call (90); no `rescue` of a namespaced class beside a same-named top-level one (89: `I18n`'s errors subclass `::ArgumentError` directly, no `I18n::ArgumentError`); runtime `strftime` patterns only through `Template::Helpers.time_tag_strftime` (96); pass locals, never ivars, to stored lambdas (97); a value threaded through several gen methods is recomputed by each consumer (94).

## Decisions

The controller's rulings on the survey's mismatches (R1–R9), then the plan's own (D1–D20). Each is a fact the tasks build on.

- **R1. The `Authentication` concern.** As Rails 8 does, the generator writes `app/controllers/concerns/authentication.rb` (`extend ActiveSupport::Concern`; `included do before_action :resume_session; before_action :require_authentication; helper_method :authenticated? end`; private `authenticated?`, `resume_session`, `require_authentication`, `require_admin`, `start_new_session_for`, `terminate_session`, `after_authentication_url`) and `ApplicationController` gets `include Authentication` (inserted after `CLASS_LINE`). On a re-run over a 0.4 application, whose code sits inside `application_controller.rb`, the generator writes the missing files and prints the manual changes (§14); `--force` overwrites the generator's own files.
- **R2. Session limits.** The spec's "session_max_age" for the cookie-level absolute limit means `Config#session_absolute_max_age`; the plan uses the real names. "Remember me" unchecked needs a browser-session cookie (no `Max-Age`, no `Expires`). The generated code stamps two session keys, `Session::LIFETIME_KEY = "_lifetime"` (seconds, the per-session absolute limit) and `Session::BROWSER_KEY = "_browser"` (`"1"` = no `Max-Age`), through `Cybertrain::Session#stamp_lifetime!(seconds, persistent)`; `SessionStore#call` reads them in place of `@absolute_max_age` and `@max_age`. Recorded as a deviation in §18.
- **R3. YAML.** Spike item 6 first tries Spinel's Psych (`require "yaml"`) in a gen-shaped compiled program on rails-i18n's `en.yml` and `ja.yml` and a 2,000-key generated file. If it compiles and parses them as CRuby's Psych does, gen uses Psych and refuses anchors, aliases, tags and multi-document files itself (a line pre-scan), so the accepted subset matches §8. Otherwise gen uses the hand-written subset parser of §8. The fixtures are fetched from GitHub in Task 1 and vendored under `test/fixtures/i18n/rails-i18n/` with their MIT license and source commit.
- **R4. Per-request locale.** `I18n.locale` is thread-local (`Thread.current[:cybertrain_i18n_locale]`, the precedent of `cybertrain/db/pool.rb`'s `TRANSACTION_KEY`), reset to the default locale at the top of `Controller#run_action`. The spike checks it compiles under Spinel; the fallback is a `locale` field on `Cybertrain::Context`, threaded explicitly (see Task 4's fallback step).
- **R5. Names.** String lookups and Array lookups (day and month names) are separate methods: `I18n.t` / `I18n.translate` → String, `I18n.translate_list` → `Array<String>`; generated `Gen::Locales.lookup` → String or nil, `Gen::Locales.lookup_list` → `Array<String>`. `TimeZone.remember(path, zone)` is renamed `TimeZone.remember_zone` so the `sessions.remember` column keeps the spec's name. NAME_HOMES rows (Task 1): `t`, `translate` → `cybertrain/i18n.rb cybertrain/controller.rb`; `l`, `localize`, `translate_list`, `locale`, `with_locale`, `default_locale`, `available_locales`, `locale_available?` → `cybertrain/i18n.rb`; `preferred_locale` → `cybertrain/http/request.rb`; `human_attribute_name` → `cybertrain/i18n.rb cybertrain/generator/models_emitter.rb`; `lookup`, `lookup_list` → `cybertrain/generator/locales_emitter.rb cybertrain/locales/bundled.rb`; `admin?` → `cybertrain/cli/authentication.rb`; `remember` → none (`%w[]`); `deliver_later` → `cybertrain/mailer/later.rb cybertrain/mail_message.rb`; `allow_unauthenticated_access` → `cybertrain/controller.rb cybertrain/cli/authentication.rb`; `password_reset_token` → `cybertrain/cli/authentication.rb`. `NAME_CANDIDATES` gains `translate localize locale remember admin?`.
- **R6. The user command** is generated in both sign-up and invite-only modes (`app/commands/user_command.rb`, required from `bin/<app>.rb`; the boot warning stays invite-only) and gains `./<app> user admin EMAIL` and `./<app> user unadmin EMAIL`; `./<app> user EMAIL [PASSWORD]` (create, or set the password) is unchanged. There is no `list` subcommand today and none is added.
- **R7. End-to-end acceptance** (§15 item 10) follows the existing precedent, which is CI only (`.github/workflows/ci.yml`'s gem e2e jobs compile a generated app and run its generated `test/authentication.rb`). The plan puts that work in `script/auth-e2e VARIANT...` (variants `signup`, `invite`, `confirmable`, `upgrade04`), runnable locally with the pinned toolchain and called by a new CI step. The 0.4 upgrade is pinned by `test/fixtures/auth_04_app/`, an application generated once by v0.4.1's generator (Task 16).
- **R8. The jobs page** is Ruby-built HTML (`cybertrain/jobs_page.rb`): its strings go through `I18n.t` in Ruby, under `cybertrain.jobs_page.*`.
- **R9. `l` with dictionary formats** goes through `Template::Helpers.time_tag_strftime` (rule 96); `I18n.l` first replaces `%a %A %b %B %p %P` with the dictionary's names, then hands the pattern to the walker.
- **D1. `I18n` is a top-level module** in `cybertrain/i18n.rb` (as `ActiveSupport` is in `cybertrain/active_support.rb`), so application code writes `I18n.t` as in Rails. Errors: `I18n::MissingTranslationData`, `I18n::InvalidLocale`, `I18n::MissingInterpolationArgument`, each `< ::ArgumentError`.
- **D2. Bundled dictionaries** are `cybertrain/locales/en.yml` and `cybertrain/locales/ja.yml` (rails-i18n's keys for what the framework uses, plus the framework's own `cybertrain.*` keys and the generated authentication screens' keys), compiled into the checked-in `cybertrain/locales/bundled.rb` (`Cybertrain::BundledLocales.lookup` / `.lookup_list`) by `script/bundle-locales` (CRuby, same reader and emitter as gen); `script/bundle-locales --check` joins `script/gate`. The runtime tries: application dictionary in the locale, bundled in the locale, then both in the default locale. An application's key overrides any bundled one.
- **D3. Lookup shape.** `gen/locales.rb` is a generated `case` or a Hash constant, whichever spike item 6b measures better at 2,000 keys (the interface is the same: `Gen::Locales.lookup(key) -> String or nil`, `lookup_list(key) -> Array<String>`, empty when absent); it begins with `require "cybertrain/i18n"` (so loading the generated file alone works) and ends with `I18n.install_dictionary(Gen::Locales.resolver, Gen::Locales.list_resolver)` (lambdas passed positionally, rule 42). If item 6d finds a lambda cannot return String-or-nil, `lookup` returns `I18n::MISSING` (`"\u0000"`) for an absent key instead of nil.
- **D4. Values are Strings.** Every scalar is kept as its text (`precision: 3` → `"3"`, `false` → `"false"`, `~` → `""`); readers that need a number parse it with `Params.parse_int`. A key appears once per mapping in one file (a duplicate is refused); across files sorted by path, a later file's key wins; a key that is a mapping in one file and a scalar in another is refused naming both.
- **D5. Missing keys.** After the default locale: with `i18n_raise_on_missing`, `I18n::MissingTranslationData, "translation missing: ja.foo.bar"`; else in development and test `I18n.t` returns `"translation missing: ja.foo.bar"` and the template `t` returns `<span class="translation_missing" title="translation missing: ja.foo.bar">Bar</span>`; in production both return the humanised last segment (`"bar_baz"` → `"Bar baz"`). `I18n` cannot read `Config`: boot sets `I18n.raise_on_missing` and `I18n.mark_missing` (`!production?`), as it sets `Assets.raise_on_unknown`.
- **D6. Interpolation and options.** `I18n.t(key, options = {})`: `default:` (a String, or a Symbol naming another key), `count:` (Integer, else `ArgumentError`), `locale:`, every other key interpolated into `%{name}`; `%%{x}` is a literal `%{x}`; a `%{x}` with no argument raises `I18n::MissingInterpolationArgument, "missing interpolation argument :x in \"Hello %{x}\""`. In templates and `Controller#t`, a key ending `_html` or `.html` returns a SafeString with its interpolated values escaped.
- **D7. Plurals** (CLDR, integer counts): `count == 0` uses `zero` when the key has it (the i18n gem's rule for every locale); en and unknown locales `one` for 1 else `other`; fr `one` for 0 and 1, `many` for a non-zero multiple of 1,000,000, else `other`; ru `one` (n%10 == 1, n%100 != 11), `few` (n%10 in 2..4, n%100 not in 12..14), else `many`; ja and zh `other`. A missing category falls back to `other`. The base language decides (`pt-BR` → `pt` → en's rule).
- **D8. Lazy lookup** uses the rendering template's name, as Rails' virtual path does: `posts/index.html.erb` → `posts.index`, partial `posts/_form.html.erb` → `posts.form`, `layouts/application.html.erb` → `layouts.application`, component `__components/card_component.html.erb` → `card_component`, mail partial `mail/_password_reset.html.erb` → `mail.password_reset`. `Controller#t(".x")` resolves to `<controller_path with / as .>.<action_name>.x`.
- **D9. Models.** `Errors.new(model_key = "")` (`Model#errors` passes `Inflector.underscore(model_name)`); `full_messages` formats with `errors.format` (`"%{attribute} %{message}"`, ja `"%{attribute}%{message}"`) and `:base` messages alone (Rails; 0.4 printed `"Base ..."`). `I18n.human_attribute_name(model_key, attr) -> String`: `activerecord.attributes.<model>.<attr>`, else the humanised attribute (`author_id` → `"Author"`); gen emits `def self.human_attribute_name(attr, options = {}) = I18n.human_attribute_name("<model>", attr)` per model. `I18n.human_model_name(model_key) -> String`: `activerecord.models.<model>` (or its `one`), else the humanised key. There is no `Post.model_name.human` (`model_name` is already an instance String, rule 34).
- **D10. Validation messages** are looked up when the validator runs by `I18n.error_message(model_key, attr, type, options = {}) -> String`, Rails' chain: `activerecord.errors.models.<model>.attributes.<attr>.<type>`, `activerecord.errors.models.<model>.<type>`, `activerecord.errors.messages.<type>`, `errors.attributes.<attr>.<type>`, `errors.messages.<type>`; `count:` carries the limit for length (an Integer, choosing the plural form); numericality's limit is not a plural selector, so it is passed as `count_text:` (a String), which interpolates `%{count}` without choosing a plural form (D6's Integer check applies to `count:` only). `belongs_to`'s message keeps the key `blank` ("can't be blank", §14). The length messages take rails-i18n's plural forms (minimum 1 reads "character"; 0.4 said "characters").
- **D11. Number helpers by locale** apply to the template helpers (they read `number.format`, `number.currency.format`, `number.percentage.format`, `number.human.decimal_units`, `number.human.storage_units` of the current locale); `Cybertrain::NumberHelper` called from Ruby keeps its explicit English defaults. `pluralize` uses the English inflector only when the locale's language is `en`; elsewhere the word is returned unchanged unless a plural is given (Rails has no ja inflections either). Generated error headers use `errors.template.header` with `count:` instead of `pluralize`.
- **D12. Framework-only keys** live under `cybertrain.*` (`cybertrain.jobs_page.*`, `cybertrain.pager.*`, `cybertrain.helpers.submit.no_model` = "Save changes", also `submit_tag`'s default); Rails' own keys keep Rails' names; the generated screens' keys follow lazy lookup (`sessions.new.title`, `passwords.create.sent`).
- **D13. `Request#preferred_locale(available) -> Symbol`** parses `Accept-Language` by q-value then position, matches a tag exactly then by language (`ja-JP` → `:ja`), never calls `to_sym` on the header, and answers `I18n.default_locale` when nothing matches. `I18n.locale = value` accepts a Symbol or a String, compares with the available locales' names (never `to_sym` on input) and raises `I18n::InvalidLocale, "\"xx\" is not an available locale"`; `I18n.locale_available?(value) -> Boolean` is the check.
- **D14. `allow_unauthenticated_access(only: [], except: [])`** becomes a `Cybertrain::Controller` class method (it calls `skip_before_action(:require_authentication, ...)`): a concern's `class_methods` live in `gen/concerns.rb`, which loads after the controllers whose class bodies call it, and its forwarder's `self` would be the concern (`SKIPS[self.name]`). A 0.4 application's own `def self.allow_unauthenticated_access` keeps overriding it.
- **D15. Tokens** (`Cybertrain::Token`): `"<id>--<expires epoch>--<64 hex>"`, the hex an HMAC-SHA256 of `"<purpose>:<id>:<expires>:<bound_to>"` keyed with `Crypto.derive_key(secret_key_base, "cybertrain token")`. The reset token binds `password_digest` and lasts 15 minutes; the confirmation token binds the address being confirmed and lasts 3 days (`User::CONFIRMATION_TOKEN_TTL`, a generated constant). No `.` in a token (the route format split).
- **D16. Mail.** `Cybertrain::MailMessage` (`to`, `subject`, `body`, `html`, `from`; `deliver_later -> Integer`, `deliver_now -> nil`) is what a generated mailer method returns, so `PasswordsMailer.reset(user, url).deliver_later` reads as in Rails. Links in mails take their base from the application setting `base_url` (`<APP>_BASE_URL`, added to `config/app.rb` by the generator), else `request.base_url` when not in production or when `Config#checked_hosts` is non-empty; otherwise `create` logs `[ERROR] password reset mail not sent: set <APP>_BASE_URL (or CYBERTRAIN_HOSTS)` and still answers the same page — a forged `Host` never reaches a reset link.
- **D17. Lockout** counts with `User.where(id: user.id).increment(:failed_attempts)` (atomic); at `auth_lockout_attempts` the row gets `locked_until = now + auth_lockout_period` and `failed_attempts = 0`; while locked, `authenticate_by` runs the dummy password hash and answers nil (same message, same timing class). `auth_lockout_attempts = 0` turns lockout off; `auth_idle_timeout = 0` turns the idle limit off.
- **D18. Remember me and idle time** are checked on the session row in the generated `resume_session` (`remember` → limit `auth_remember_for`, else `session_absolute_max_age`; `last_active_at`, nil read as `created_at`, older than `auth_idle_timeout` ends it; touched with `update_columns` at most once a minute) and at cookie level by R2's stamp. The generated tests prove the day-15 / day-30 / day-14 / 7-idle-day cases by backdating `created_at` / `last_active_at` (0.4's absolute-expiry test does the same); the cookie-level stamp is proved in the framework's `test/session.rb` with `SessionStore#fixed_now=`.
- **D19. Re-runs.** Marker-based edits (routes, `bin/<app>.rb`, `config/app.rb`, the layout's nav) are applied on every run, as 0.4's are. For each file the generator writes whole that exists with other content, it prints a unified diff (`--- a/<path>` / `+++ b/<path>`, 3 lines of context, `patch -p1` applies it) headed `manual  <path>: apply this diff by hand, or re-run with --force to overwrite the file`; `--force` writes the new content instead (`force  <path>`). For `application_controller.rb` holding 0.4's inserted block (`LEGACY_APPLICATION_CONTROLLER_BLOCKS`, the text of v0.4.0/v0.4.1's `application_controller_block`, identical in both), the diff removes the block and adds `include Authentication`; `--force` applies that change only when the block matches exactly. A 0.4 `create_users` migration without `admin` gets a new `<v>_add_authentication_columns.rb` (with `--confirmable` it also backfills `confirmed_at` for existing users).
- **D20. New generated tests are new files** (`test/passwords.rb`, `test/accounts.rb`, `test/remember_me.rb`, `test/lockout.rb`, `test/admin.rb`, `test/confirmations.rb`) using 0.4's `AppTest` API (`boot`, `form_token`, `user`, `sign_in`) plus a new `test/support/authentication_helpers.rb` (`with_smtp_receiver`, `last_mail_link`, `backdate_session`), so a re-run on a 0.4 application writes them as missing files.

## Review Focus

1. **The locale from untrusted input** (`?locale=xx`, `?locale=../en`, `?locale=JA`, a 10 KB `Accept-Language`, `Accept-Language: ja-JP;q=0.8, en;q=0.9`, `*`, `ja;q=0`): an unknown or malformed value falls back to the default without raising or creating a Symbol, q-values order the choice, `ja-JP` matches `:ja`, `q=0` excludes. Pinned in Task 8's test "preferred_locale with q-values, regions, wildcards and junk".
2. **A locale leaking between requests** (a keep-alive connection whose first request set `:ja`, then a request with no locale; an action that raised inside `I18n.with_locale(:ja)`): the second request renders in the default locale and `with_locale` restores the outer locale after an exception. Pinned in Task 4's test "the locale is reset per action and with_locale restores it on raise".
3. **YAML that YAML 1.1 types or that editors produce** (`no`, `yes`, `on`, `3`, `~`, `"%Y/%m/%d"`, `title: "a: b # c"`, a tab in indentation, a UTF-8 BOM, CRLF line endings, a trailing comment after a quoted value): values stay the Strings written (`"no"`, `"3"`, `""` for `~`), the quoted `#` is kept, BOM and CRLF are accepted, a tab is refused with its line. Pinned in Task 2's test "YAML 1.1 scalars, quotes, BOM, CRLF and tabs".
4. **Password reset enumeration and poisoning** (an unknown address, a registered one, a forged `Host: evil.example` with `base_url` set): identical status and body for both addresses, one mail only for the registered one, the link in the mail starts with `base_url`, and a token stops working after it is used once. Pinned in Task 13's generated test "reset answers the same for unknown addresses and links to base_url".
5. **Interpolation of user text and missing arguments** (`t(".greeting_html", name: "<b>x</b>")`, `t(".greeting", name: "<b>x</b>")`, `%%{x}`, `t("x", count: 0)` with and without a `zero` form, a `%{name}` with no `name:`): the `_html` key escapes the value inside a SafeString, a plain key is escaped by the template, `%%{x}` prints `%{x}`, `zero` is used only when present, and the missing argument raises `I18n::MissingInterpolationArgument`. Pinned in Task 4's test "interpolation, %%, count zero and a missing argument" and Task 5's "an _html key escapes its arguments".
